# Status — v1.1

## Image correctness and execution

The legacy NMI/fiber execution adapter was replaced by the cycle-accurate backend already included in the local NESRecomp. CPU, PPU, APU, DMA, the MMC3 mapper and interrupts now share the machine's clock. The Windows interface still uses runtime/glue.h.

The C blocks were regenerated by the compiler built from the same runtime sources. Inputs observed during testing were preserved in docs/smb3-cycle-seeds.txt. The previous executable showed 541 unexpected BRKs in 600 frames; the new backend depends neither on the C continuations nor on the legacy dispatch table.

## Audio

- The WinMM queue waits for a buffer to finish before reusing it and handles submission errors.
- Generation uses the configured rate: 44100, 48000 or 96000 Hz.
- The amount drained is the amount actually produced by the clock, without forcing 800 samples per frame.
- The frame limiter accumulates deadlines and uses 1 ms timer resolution, avoiding accumulated Sleep rounding each frame.
- The output has two channels with the same NES mono signal, with no artificial per-channel gain difference.

## Validation performed

Release build: v1.1 application and smb3-verify compiled.

Headless 3,000-frame test: 1,316 image changes, 2,395,990 mono samples produced; no CPU jam or interpreted execution in RAM/I/O. 89,334,341 native cycles and 4,770 interpreted: approximately 99.995% native. The only uncompiled instruction found was in the 4K bank $14 at CPU $CFFF, whose opcode crosses the bank boundary; the fallback executes that instruction.

All 3,000 state hashes matched between recompiled and interpreted execution. This validates the translation under the same hardware model; it is not an independent comparison with a physical console.

Full save/load: running 30 more frames after restoration produces the same memory/machine hash. The new backend serialises the complete state and does not restore the old fibers. Old saves are incompatible and rejected.

Audio over 60 frames: 43,968 samples at 44.1 kHz; 47,857 at 48 kHz; 95,714 at 96 kHz. The test allows the initial phase difference of the first frame. Audible playback on the user's device still needs retesting.

Logs: build/verify-cycle.log and build/verify-cycle.err.log. Captures: build/verify-frame-180.png, -360.png, -600.png, -900.png, -1200.png and -3000.png.

## Remaining scope

Validate controls and audio manually on the user's Windows machine, and extend gameplay/level coverage. The current test does not prove the whole game. The ROM and source folder were preserved.

## Interface v1.2

The launcher opens before the game starts, with the validated ROM, controls, settings, game and save states. The internal screens were rewritten with seven tabs, apply/discard/restore, custom selectors, and keyboard/gamepad navigation. The historical packages preserve the interface of that version; the current identity is in BRANDING.md.

Volume, brightness, scanlines, resolution, fullscreen, audio device and rate are now applied. The audio reserve uses 10 ms blocks for 20/40/60 ms of prefill. Select no longer opens the PC menu. Fixed a double close of the joystick when a SDL GameController disconnects. The device preference uses a stable path, with the GUID as fallback.

The former Win32 settings-UI verifier (smb3-ui-verify) passed when it existed: rendering of all seven pages, apply/discard, input and release of virtual buttons, hotplug. It was removed with the Win32 launcher. The 3,000-frame runtime test still passes. There was no physical validation of every USB/Bluetooth controller.

## v1.3 — widescreen preview

Canvas 426 × 240 with real scenery expansion in horizontal levels and the original HUD centred between black bars. The compositor reads the map from SRAM and graphics observed before the HUD IRQ. It does not modify CPU, physics or enemy logic.

Widescreen test: 1,800 identical machine hashes between mode on and off; 630 frames of enlarged level; camera up to 456 pixels; HUD and bars verified. Limits and references are in WIDESCREEN.md. Object activation remains original; vertical rooms and unsupported scenes stay in native format.

## v1.4 — enemies in the enlarged area

In 16:9 mode, normal object records are activated based on the wide camera, and horizontal culling uses its edges. Events and the final card keep their triggers; the five main slots still apply. Additional OAM is generated in isolated copies of the machine to draw objects in the enlarged margins. That generation does not alter the real match; early activation does change the gameplay sequence compared with native mode.

The current test compares 1,800 native/interpreted states under the same wide policy, verifies HUD/bars/centre, edge repair, early and retained enemies, unique spawn indices and save/load. A control without widescreen proves the activation difference of the first Piranha. Coverage of all levels is still pending.

Beta testers: ALEISTECH and RETROCESSO, credited in the README and on the application's Credits page.

## v1.5 — scenes, platforms and identity

The wide compositor now requires normal level mode and default raster, with no transition, final card or map exit. Prizes and bonuses return to the centred native frame with clean black margins. Objects crossing the two rebuilt 16-pixel strips are also drawn in those strips. Parts generated in the isolated copy are aligned to the OAM actually used in the frame, avoiding one-frame seams between parts of the same platform.

The presentation uses Mushroom Recompiled and the Underplay image supplied, without editing the file. Promotional artwork and earlier captures were removed from the current files. Old packages remain historical, with updated names.

## Current — Vulkan-only frontend, legacy backend removed

The SDL2 renderer fallback is gone: the frontend presents exclusively through Vulkan (`src/video_vulkan.cpp`), so the Vulkan SDK (Windows) or `libvulkan-dev` + `glslc` (Linux) are required to build `mushroom-sdl`. Without them only the engine and the verifiers build. At run time the Vulkan loader ships with the GPU driver.

The superseded NESRecomp runner backend sources under `tools/nesrecomp-src/runner/src` (legacy main loop, CPU/mapper/APU/PPU, launcher, netplay, voxel and shadow experiments) were deleted; the build only ever compiled three files from that tree. The recompiler, the generated game code and the cycle-accurate `runner/cyc` backend are untouched and remain the engine. The temporary `.tmp-shots/` captures were removed from version control, matching BRANDING.md: no screenshots ship with the project.
